# 句法解析接收协议 v2

生成流程将模型回答与持久化数据格式分开。程序对原文中的词语、缩合撇号和标点编号，模型返回首末编号与原文引用，程序统一生成字符范围与 UUID。从句用稳定标识连接，不要求模型维护数组下标或计算字符位置。

原文引用必须与编号范围一致。旧回答可按准确引用重定位，但只允许唯一匹配、从句范围内匹配或明确的 occurrence，不允许按最近位置猜测，不允许删词、替换词或拼接不连续文字。词性与句法功能继续独立保存，程序不自动修正模型的语法判断。

| 状态 | 保存与呈现 |
| --- | --- |
| 回答不可解析或无译文 | 拒绝保存；截断、服务报错和格式错误各自报告 |
| 部分解析 | 保存译文、合法范围、未确认节点与原因；界面提示未完成；覆盖数不计为完成 |
| 机械检查完整 | 没有已知的定位、引用、循环或文字覆盖缺口；仍为 AI 草稿，不能视为语法核验通过 |
| 人工导入 | 默认使用严格模式，无效节点拒绝导入 |

循环节点及依赖它们的从句和成分保留为待处理记录，不改接到根节点。解释文字的位置无效时取消其原文定位，保留说明。混合输出按完整 JSON 对象扫描，字符串中的花括号不影响对象边界。

保存前以 SentenceAnalysisSchema 统一数据格式和字段顺序。部分结果替换以前有效解析时保存历史快照，快照沿用既有记录类型并随书库备份导出。当前界面没有新增历史快照恢复按钮。

材料指纹更新为 source-anchors-v2。部分解析不进入批量跳过条件。取消、原文版本变更、分句变更和旧请求晚到的写入检查继续生效。旧数据无需整体迁移，reception 为可选字段。

实际模型复测使用此前五句原文：DeepSeek、MiMo、Luna 各获得五份完整回答，Gemma 五次及短请求对照均返回 HTTP 500。十五份回答全部在真实 controller 与校验数据格式的测试存储中保存、关闭后重开，并以实际客户端渲染函数检查原文完整性。此验证没有替代已安装桌面宿主的真实点击验收。
